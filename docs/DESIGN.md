# Rec Cue! 設計メモ

## 1. 経緯

2026-10-20、Windows 標準の Snipping Tool で録った会議の録画が、メモリが逼迫した PC で 2 本続けて保存に失敗した。
- 録画は一時ファイルに残っていて、どちらも映像のトラックが音声より短かった (録画中のコマ落ち)。PC 全体のメモリ逼迫の中で Snipping Tool 自身のメモリが膨らみ、最後の保存で失敗したと見ている。
- 別の日には相手の声が入らなかった。Snipping Tool は PC の音声を既定の再生機器からしか録らないので、会議アプリの出力先が既定と違うと入らない。

Rec Cue! はこの 2 点を避けるために作った (2 の方針)。

## 2. 方針

Snipping Tool の弱点をそのまま避ける。
- 一時ファイル → 保存、の工程を持たない。最終ファイルへ直接書き、停止時は Finalize だけ (実測 13〜24 ms)。
- 落ちても残る形式 (fragmented MP4・約 0.4 秒ごとの断片)。
- 映像は GPU のまま (CPU にコピーしない)。CPU 負荷を抑え、メモリ逼迫の影響を小さくする。
- 時計は 1 つ (QPC)。映像の各コマも、音声の各パケット (WASAPI が返す QPC 時刻) も同じ時間軸に置く。コマが落ちても音と映像はずれない。
- 「相手の声」を録り損ねない: 再生機器を自動で選び、録画中に増えた機器も足す。機器ごとの音量を画面と 10 秒ごとのログに出す。

## 3. 構成

```
main.cpp      ウィンドウ (Win32・PerMonitorV2) とコマンドライン (--list-devices / --probe-levels / --record / --verify-file / --ui-snapshot)
recorder.cpp  1 回の録画: 映像スレッド (15 fps の刻み) ・音声エンジン・書き出し・10 秒ごとの stats・sessions/<sid>.json・
              一時停止 (0.4.0〜・止めた区間を映像と音声の時間軸から同じだけ抜く)
video.cpp     DXGI Desktop Duplication。モニターを持つ GPU で D3D11 デバイスを作る。ロック・UAC・画面変更で失われたら 0.5 秒ごとに作り直す。
              カーソルは GDI 互換テクスチャに DrawIconEx で描く。--test-pattern は合成映像。
writer.cpp    Media Foundation の Sink Writer。BGRA テクスチャ → (Video Processor MFT) → H.264 ハードウェア MFT / AAC。
              GPU テクスチャは IMFVideoSampleAllocatorEx のプール (最大 4 枚) から借り、エンコーダーが返すまで再利用しない。
              fMP4 は Finalize 後に tkhd/mdhd のトラック長をその場で書き込む (AVFoundation が 0 秒と読む対策・バイト位置は動かさない)。
              録音だけは MP3 / M4A (Sink Writer) と WAV (自前で書き、見出しの長さを 1 秒ごとに書き直す) (0.4.1〜)。
audio.cpp     WASAPI (共有モード・Windows の変換で 48 kHz 2ch float)。マイク 1 つ + ループバック N 個。
              パケットの QPC 時刻からリングバッファ上の位置を決め、ずれは 1 サンプルずつ詰める (クロック差)・40 ms 超は飛ばす (無音区間・停止)。
              150 ms 遅れで混ぜて 50 ms ごとに AAC へ。マイクと PC の音声のメーター (100 ms)。
config.cpp    %USERPROFILE%\.rec-cue\config.ini
shot.cpp      スクショ (0.3.0〜): 自分の窓を取り込みから外して GDI で 1 画面を撮り、WIC で PNG・クリップボードに CF_DIB
indicator.cpp 録画中・録音中の印 (0.3.0〜): タスクバーの重ね絵の点滅と、画面左上の小さな丸 (録画に写らない窓)。
              タスクバーのサムネイルのボタン (0.4.0〜): 録画・録音 / 一時停止・停止
ui_draw.cpp   画面の見た目 (Direct2D)。案内役の SD の絵は RCDATA から WIC で読む
update.cpp    アップデート (0.5.1〜): GitHub の最新の版を WinHTTP で尋ね、受け取った exe を大きさ・SHA-256・--version で確かめて入れ替える
```

## 4.1 コードレビュー (2026-10-20) で直したもの

- fMP4 のトラック長の書き戻しで、一時的な vector の要素を指したまま読んでいた (解放済みメモリ・ASan で確認)。名前付きの変数に保持し、箱の大きさの検査と、開けないときの再試行 (約 1 秒) を足した。書き戻せたかは `duration_patched` に出る。
- 録画中の再生機器の追加を、音声スレッドから別スレッド (3 秒ごと) に移した。開けなかった機器は 30 秒あけて再試行し、空の一覧を参照しない。切れた機器は COM オブジェクトとバッファを放す。
- 録画中にマイクが外れたら画面を「マイクなし」にし、5 秒ごとに選び直す。
- 解像度・位置が変わったら、録画の大きさのまま切り取り / 黒の余白にし、カーソルの原点を追う。
- エンコーダーが 5 秒フレームを受け取らなければ自動停止。ログオフ・シャットダウン前に保存。
- 統計の持ち越し (2 回目の録画) と、長時間の無音カウンターのあふれを直した。

修正後の試験: 自己試験・試験音 (ずれ 118〜124 ms で一定)・自動選択 (内蔵マイクと既定のスピーカーの音を検出)・60 秒連続 (private 209〜214 MB 横ばい・コマ落ち 0) すべて合格。

## 4.2 画面 (0.2.0・2026-10-21)


- **方向**: 検証用 PC はダークモード (表示 125%)。深い墨色の地 (#171B23→#0E1117) に真鍮色 (#C8A96A) の細線と差し色、文字はアイボリー (#EEE7D7)、録画にかかわるものだけ深紅 (#B8312A)。古い録音機の銘板のような落ち着きに、今の Windows 11 の平らな面と角丸を合わせる。タイトルバーも地と同じ色にし (DWM)、機器の一覧 (ポップアップメニュー) もダークにする。
- **構成**: 子コントロールをやめ、`ui_draw.cpp` が `UiModel` (状態の写し) から Direct2D で 1 枚に描く。`main.cpp` は状態・マウス・キーボード・メニューだけを持ち、当たり判定は描画と同じ矩形を使う。`--ui-snapshot` は同じ描画を WIC のビットマップに描いて 6 状態の PNG にする (ウィンドウを開かない)。
- **要素**: 録画ボタン (真鍮の輪と深紅の玉。録画中は ■ になり、輪が 2 秒周期で呼吸する) / 時計 (Segoe UI Variable Display Light・等幅数字) と REC・確認中の札 / 銘板 (Georgia Italic の「Rec Cue!」と SCREEN · MIC · PC AUDIO) / 中央に菱形を置いた細線 / マイクと PC の音声の行 (選択欄は確認中と録画中に「自動 → いま使っている機器名」、メーターは 52 個の LED と 1.5 秒のピーク保持と目盛り) / 保存先 (英数字のフォントを先に当て、日本語フォントで「\」が「¥」になるのを避ける) / 3 つのボタン。
- **軽さ**: 100 ms の刻みは録画中・確認中・保存中だけ動かす。待機中の CPU は 0 (旧版は 0.10%・常に刻んでいた)。待機中の working set は 65 MB (private 37 MB・旧版 19 MB) で、GPU の描画のぶん増えた。exe は 767 KB (旧版 732 KB)。

コードレビュー (2026-10-21・重大な指摘なし) で直したもの:
- `--quit`: 録画ボタンを押した直後の準備中 (約 1.3 秒) はタイトルがまだ「録画中」でなく、閉じる確認が出る余地があった → 準備に入った時点でタイトルを変える。
- 機器の一覧を開いている間にショートカットで録画が始まると、選んだ機器が録画中に書き込まれた → 一覧を閉じた後に状態を確かめ直す。
- uxtheme の名前のない関数 (ダークのメニュー) を版の確認なしに呼んでいた → Windows 10 1903 (ビルド 18362) 以降だけ呼ぶ。

0.2.0 の試験: 自己試験 121 コマ・コマ落ち 0 / 試験音のずれ 109.2・114.3・113.7 ms (一定) / 60 秒連続 901 コマ・コマ落ち 0・private 207 MB 横ばい・CPU 2%。いずれも配置前の版を `EXE=` で回した (使用中の版には触れていない)。

## 4.3 0.3.0 (2026-10-22) — 見た目の作り直し・最前面・スクショ・録音だけ・録画中の印


- **アイコン**: NovelAI V5 で 8 案 → **S-L1P1** (黒髪のポニーテール・赤縁の眼鏡・紺のブレザー・冊子を顔の横に・淡いバラ色の地・seed 26102201)。`tools/make_icon.py` で角丸の四角 (半径 20%) に収め、16〜256 px の 10 サイズの .ico にした。
- **画面**: Gemini 4 Argon (`google/gemini-4-argon`) に、窓の大きさ (480 × 272 固定)・要素・Direct2D で描ける制約 (ぼかし無し・Windows の書体だけ) を渡し、HTML と寸法の JSON で 3 方向を作らせた (計 $0.55)。**A 案 Executive Dark** を採用: 地 #13161C、面は 1 px の枠と上辺の明るい線 (影の代わり)、差し色は水色 #38BDF8 だけ、録画は深紅 #E11D48、録音は青 #3B82F6、時計は Cascadia Mono、メーターは連続の帯 (#0284C7 → #38BDF8 → #2DD4BF) とピーク保持。A 案の左上の丸い顔は SD の立ち絵に替えて右下に置き、そのぶん保存先と下の 3 ボタンを短くした。上の帯は［最前面］［録音］［スクショ］。
- **SD の案内役**: 同じ人物の SD を 6 案 → 待機中は SD-P1b (冊子を両手で持つ)、録画・録音中は SD-P2a (冊子にペンで書き込む = 記録を取っている)。`tools/cutout.py` で白い地を抜き (画像の縁につながる白だけを地とし、その周り 3 px は白を差し引いて半透明に)、RCDATA で exe に入れた。表示の大きさ (高さ 82 DIP) に WIC (Fant) で縮めてから 1:1 で描く (Direct2D の拡大縮小は線形でちらつくため)。
- **最前面**: HWND_TOPMOST の切り替え。`topmost` に保存して次の起動で戻す。タイトルの右クリックのメニューにも「最前面に表示」。
- **スクショ**: 自分の窓に `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` → `DwmFlush` 2 回 → GDI の BitBlt で録画と同じ画面 (monitor) を撮る → 元に戻す。窓を縮小・非表示にしないので画面がちらつかず、最前面に固定していても後ろの画面が写る (外せない古い Windows では一瞬隠す)。PNG (24 bit) は別スレッドの WIC で `.part` に書いてから名前を変える。クリップボードには CF_DIB (不透明)。録画中に撮ったものは sessions の `screenshots` に録画開始からの秒数と一緒に残る。1920 × 1080 で撮影 44 ms・保存 29 ms・304 KB (10-22 実測)。
- **録音だけ**: 映像のストリームを作らず AAC だけの fMP4 (`.m4a`)。録音中は 50 ms ごとに時計・10 秒の stats・停止条件だけを回す。working set 30 MB (録画は 204 MB)。録画中は始められない (録画にも音声が入る)。
- **録画中の印**: タスクバーの重ね絵 (`ITaskbarList3::SetOverlayIcon`・小さいアイコンの大きさに白い縁の丸・明るさ 5 段を REC の札と同じ 2 秒周期) と、画面の左上の 8 DIP の丸 (`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOPMOST` の窓・`UpdateLayeredWindow`・`WDA_EXCLUDEFROMCAPTURE` で録画にもスクショにも写らず、クリックは下の窓へ。2 秒ごとに最前面へ上げ直す)。録画は録っている画面に赤、録音はメインの画面に青。外せない Windows では録画中の丸は出さない (録画に写るため)。
- **状態の色**: 録画は赤 (窓の上端 2 px の帯・中央の帯・REC の札・■)、録音は青 (同じ場所・AUDIO の札・上の「録音中」)、警告は琥珀 (中央の帯・PC の音声の行・「無音」の札)、スクショと保存の知らせは水色 (4 秒で元の表示に戻る)。

コードレビュー (2026-10-22・重大な指摘なし・中 2 件・軽 4 件) で直したもの:
- スクショを PNG の保存前に数え、録画の記録 (`screenshots`) にも載せていた → 保存できた後に、撮ったときと同じ録画が続いているときだけ数える (撮った時点の秒数で記録。保存中・停止処理中・次の録画に紛れ込まない)。
- 保存先が応答しない場所 (切れたネットワークの共有) だと、閉じるときに PNG の書き出しを無期限に待ち、窓の無いまま残って次の起動を妨げた → 録画の保存を先に済ませ、PNG は 3 秒まで待つ。それでも終わらなければ処理を打ち切って終了する (ログオフ時も同じ 3 秒)。
- クリップボードを 1 回しか開こうとしなかった → 15 ms おきに最大 10 回。仕事の画面が外に出ないよう、クリップボードの履歴 (Win+V) とクラウドのクリップボードには載せない (`CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` = 0)。
- 知らせ: 続けて出た知らせが前の知らせを「元の表示」として覚えることがあった → 表示中かどうかを別に持つ。新しく出た録画の警告は知らせより先に出す。中央の帯の琥珀色は録画の警告だけで決める (録音のショートカットを断る知らせなどでは変えない)。保存の失敗は 8 秒出す。
- 案内役の絵が読めなかったとき、描くたびに読み直していた → 描き先と DPI ごとに 1 回だけ試す。
- そのまま (仕様): スクショの瞬間 (約 60 ms) は Rec Cue! の窓が録画からも外れる (15 fps で 1 コマほど)。


0.3.0 の配置 (10-22 22:29): `--shot-selftest` 合格 (96 px の四角が窓を除かない画像に 9216 px・除いた画像に 0 px・除く処理 28 ms + 撮影 32 ms)。起動の記録はショートカット 3 つの登録とタスクバーの準備ができたこと (`ui.taskbar`)。

0.3.0 の試験 (10-22・配置前の版を `EXE=` で): 自己試験 121 コマ・コマ落ち 0 / 試験音のずれ 109.2・103.9・114.4 ms / 録音だけ 8.02 秒・138 KB・ずれ 118.2・117.9・120.9 ms・streams は audio だけ / 60 秒連続 901 コマ・コマ落ち 0・private 207 MB 横ばい・CPU 1.7% / スクショ 撮影 44 ms + 保存 29 ms。exe は 1.0 MB (アイコン 153 KB と SD の絵 76 KB を含む)。

## 4.8 0.4.1 (2026-10-26) — 録音の形式 (MP3 / WAV / M4A)


- 録音だけの形式を `audio_format` (mp3 / wav / m4a・既定 mp3) で選ぶ。窓では録音の帯の「録音」の左の「MP3 ▾」(待機中と音量の確認中だけ出る) から。録画はいつも MP4 (H.264 + AAC)。
- **MP3**: Sink Writer に MP3 のコンテナー (`MFTranscodeContainerType_MP3`) と `MFAudioFormat_MP3` を指定し、Windows に入っている MP3 エンコーダー (MP3 Encoder ACM Wrapper MFT・Windows 8 以降) で 48 kHz ステレオ・`audio_kbps` にする。フレームの並びなので、落ちてもそこまで再生できる。
- **WAV**: 16 ビット PCM 48 kHz ステレオを、Media Foundation を通さず自前で書く (RIFF の見出し 44 バイト + データ)。見出しの長さを 1 秒ごとに書き直すので、落ちても 1 秒ほど前まで再生できる (Media Foundation の WAVE の書き出しは仕上げのときにしか長さを書かない)。RIFF の大きさは 32 ビットなので、データ 4,000,000,000 バイト (5 時間 47 分) で自動で止めて保存する (`session.wav_full`)。
- M4A (AAC・fragmented MP4) は今までどおり選べる。一時停止は混ぜた音から抜いているので、どの形式でも同じように効く。
- 記録: sessions の `audio_file`、ログの `writer.open` (`audio only / mp3 128 kbps / mp3`・`pcm 1536 kbps / wav`)・`ui.audio_format`。しおりの台詞で「.m4a で保存」と言っていた 5 本を形式によらない言い方にし、形式のヒントを 2 本足した (1,144 本)。
- **動画の形式 (おすすめを聞かれて)**: MP4 (H.264 + AAC・fragmented) のままにする。MKV は落ちても残る点は同じで、Mac の QuickTime などで開けない分だけ不利。WebM (VP9 / AV1) は Windows の標準の部品では GPU で圧縮できないことが多く、CPU で圧縮すると重い。H.265 (HEVC) の MP4 は同じ画質で 3〜5 割小さく GPU でも圧縮できるが、Windows で再生するには有料の HEVC ビデオ拡張機能が要り、渡した相手が再生できないことがある → 容量に困ったときに選べるようにする候補。

- **構成** (`mac/`・Swift / SwiftPM・Xcode は不要): ScreenCaptureKit (1 画面・Mac の音・マイクを 1 本の流れで取り、時刻はすべてホストの時計) → 15 fps の刻みで最新の画面を AVAssetWriter (H.264 は VideoToolbox・AAC) に書く。刻みは時間軸の各コマの位置の半コマ後に打ち、その時点の最新の絵をそのコマとして書く (画面が変わらなくても同じ絵を書くので、Windows 版と同じくコマ数は一定)。音は Mac の音とマイクを 48 kHz の 1 本の時間軸に時刻で並べ、150 ms 待ってから混ぜる (音が無い間は無音・10 ms までのずれはつなぐ)。Windows 版とコードは共有せず、ログ・`stats`・`sessions/<sid>.json`・`--verify-file` の形をそろえた。

**コードレビュー (2026-10-27・別のエージェント) で直したもの** — 指摘 14 件のうち 12 件を 4 回に分けて直し、回ごとに合成の窓の試験で確かめた。

- **音を捨てない**: 書き出しが受け付けないとき、音を捨てずに持ち越す (`audio.waits`・`backlog`)。AAC は詰めて書かれるので、1 回でも抜けると以降の音が前にずれる (レビューで 200 ms の穴を作ると、2.5 秒の印が 2.3 秒に動いた)。音の固まりを作り損ねたときも時間軸を進めない。
- **開始と停止の端の音**: `startWriting` を時計の起点より前に済ませ、起点の直後にミキサーを始める (開始直後の 40〜120 ms が無音だった → `first_ms` 0.0)。停止は終わりの時刻を決めてから、刻みの遅れと音の待ち時間の分だけ取り込みを続け、終わりまでを書き切る (最後の約 30 ms が欠けていた)。
- **途中で終わるとき**: 取り込みが止まった (メニューバーの停止は `user`、ほかは `stream`)・書き出しの失敗 (`writer`)・ディスクの空きが 500 MB 未満 (`disk`)・Ctrl-C / kill (`signal`) のどれでも、通常の手順でファイルを仕上げて `ended_by` を残す。`stream`・`writer`・`disk` は `ok: false`。結果の `complete` (映像のサンプル数が書いた数と同じで、音が終わりまで入っている) も `ok` に含める。`complete` は直したその日に、60 fps で終わりが刻みの位置にちょうど重なると長さ 0 のコマが切られる誤りを見つけた (刻みの数を 1/48000 s の整数で数えるように直した)。
- **絵の選び方**: 「刻みの位置 + 半コマまでに取り込んだ最新の絵」(サンプルホールド)。「いちばん近い絵」は、絵がまばらに届くと変化を早く映した (動かない窓の 60 fps で −12.9 ms → 直して −6.8 ms・半コマは 8.3 ms)。取っておく絵は 3 枚 (ScreenCaptureKit が一度に貸す 8 枚に、書いた絵と圧縮中の分も収める)。

- **後回し**: 長い録画での時計のずれ (マイクの時計がホストより 50 ppm ずれると約 3 分ごとに 10 ms の継ぎ目。`gaps` / `overlaps` に出る) は、長い試験で確かめてから。macOS 27 の SDK では `expectsMediaDataInRealTime` と `AVAssetWriterInputPixelBufferAdaptor` が非推奨 (対象を 27 以上に上げると警告で止まる)。
- **未試験**: 取り込みが途中で止まったとき・書き出しの失敗・ディスク不足・スリープ・画面の抜き差し・多チャンネルのマイク。直した後の 60 秒の連続 (901 コマ・落としたコマ 0・CPU 0.8%・18 MB) と 7 秒の強制終了 (6.0 秒分が再生可) は直す前と同じ。

**一時停止 (2026-10-27・Step 2)** — Windows 版 (4.7) と同じく、止めた区間を映像と音の時間軸から同じだけ抜いて 1 本につなぐ。

## 4.11 0.5.0 (2026-10-30) — 設定の画面・保存先の変更・ログを取得


- **設定の画面**: 歯車はメニューをやめ、窓の中を設定の画面に切り替える。窓の大きさ (480×340 DIP) と見出し・しおり・吹き出し・録画中の線はそのままにして、帯と行の場所に「保存先」「ショートカットキー」「ログと情報」の 3 つの区切りを置く。部品は元の画面と同じ欄・ボタン・色 (A 案) で描く。戻るのは ← ・歯車・Esc。録画を始めると (ショートカットやタスクバーからも) 元の画面に戻る (帯が時間と ■ を見せるため)。録画中に開いたときは、見出しの「設定」の横に REC / AUDIO / PAUSE の札と時間を出す。
- **保存先**: 「録画・録音」と「スクショ」の 2 行。欄はエクスプローラーでそのフォルダーを開き (録画中も使える)、「変更」は Windows のフォルダーの選択の画面 (`IFileOpenDialog`・`FOS_PICKFOLDERS`・今のフォルダーから) を開く。Snipping Tool の設定の「スクリーンショットのフォルダー」(パスを押すと開き、「変更」で選ぶ) と同じ形。選んだフォルダーに空のファイル (閉じると消える) を作れるか試してから書く (書けない場所で次の録画が始まらないように)。既定の場所 (`ビデオ\画面録画`・スクショは録画と同じ場所) を選んだときは値を空のままにして、既定に付いていくようにする。「変更」は録画中・録音中は押せない (マイクの欄などと同じく、録画中は設定を変えない)。
- **ショートカットキー**: 3 つを表示だけする (変えるのは設定ファイル。画面には出さない)。ほかのアプリが使っていて登録できなかったキーは琥珀色で「使用中」。
- **設定ファイル**: 画面から開く入口を外した (「設定ファイルを開く」・ショートカットの「設定ファイルで変える」)。ファイル (`config.ini`) は設定の保存先として今までどおり読み書きする。設定ファイルにしか無い項目 (fps・画質・音質・音量の補正・ファイル名の先頭・ショートカットの変更) は画面に出さず今の値のまま (本人の選択「ご依頼の範囲だけ」)。それらを案内していたしおりの台詞 8 本は外した。
- **ログを取得**: 「ログを見る」(メモ帳で今日のログ) を置き換え、直近 7 日の logs と sessions・config.ini・about.json (版・Windows のビルド・日時) を 1 つの ZIP にまとめて「ダウンロード」に置き、エクスプローラーでそのファイルを選んだ状態で開く (メールやチャットにそのまま添付できる)。Windows には呼べる ZIP の書き手が無い (Shell の圧縮フォルダーは非同期で進み具合の窓も出る・`tar.exe` を外から呼ぶのは避けた) ので、自前で書く (`src/logpack.cpp`・圧縮しない stored・CRC-32・UTF-8 の名前)。1 週間のログは数 MB なので圧縮しなくても渡せる。書くのは別のスレッドで (ダウンロードがネットワークに向いた PC で窓を止めない)、閉じるときはスクショの PNG と同じく 3 秒まで待つ。
- **録音の形式のメニュー**: 「MP3 ▾」のメニューの大きさ・音質の説明を外し、MP3 / WAV / M4A の名前だけにした。
- **Mac 版** (10-30 に追加・本人の選択「Windows 版の後に」): 同じ寸法・色・部品で描く (`mac/Sources/RecCue/WindowView.swift`)。「変更」は NSOpenPanel を窓のシートで開き (今のフォルダーから・新しいフォルダーも作れる)、欄は Finder で開く。ログの ZIP は同じ形 (`mac/Sources/RecCue/LogPack.swift`) を「ダウンロード」に置き、Finder でそのファイルを選んで見せる (about.json には macOS の版)。ショートカットは ⌃⌥R のように Mac の書き方で出す。0.4.2 までの言い方に戻していた `mac/shiori-mac.txt` の差分は消した。前の歯車のメニュー (設定ファイルを開く・ログを見る・Rec Cue! について) は、本人が手で確かめた後に消した。



## 4.12 0.5.1 (2026-10-31) — アップデートの通知


- **確かめ方**: 窓を開いたとき (WM_CREATE) に別のスレッドで `https://api.github.com/repos/keigoly/rec-cue/releases/latest` を 1 回だけ GET する (WinHTTP・`WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY` でシステムのプロキシ設定と PAC に従う・タイムアウトは名前解決と接続 10 秒・送受信 15 秒)。送るのはその問い合わせだけ (利用者や PC を表すものは付けない・User-Agent は `RecCue/<版>`)。返事の JSON は小さな自前の読み手で読む (外部のライブラリを使わない方針のため・`src/update.cpp`)。タグの `v` を外した版を数字ごとに比べ、今の版より新しく、`update_skip` の版でなければ知らせる。返事が無い・読めないときは何も出さない (ログだけ)。`update_check=0` で尋ねない。
- **知らせ方**: OBS と同じく、起動の直後にその場で選ばせる。何も録っていなければ、窓の中をアップデートの画面 (設定の画面と同じ作り: 見出しに ← と「アップデート」) に切り替え、版・今の版・公開日、変更点 (Releases の本文の「## x.y.z の変更」の箇条を 1 行ずつ・6 行まで)、OBS の 3 つの選択「今すぐ更新」「あとで」「この版をスキップ」と「詳しく」(Releases のページ) を出す。しおりは「新しい版 {v} が出ております。更新なさいますか。」。録画中・音量の確認中に見つかったときは画面を切り替えず、歯車に青い点を付け、設定の画面の版の欄に「{v} に更新できます ›」を出す (押すとアップデートの画面)。録画を始めると (ショートカットからも) 元の画面に戻る。
- **あとで / この版をスキップ**: あとでは何も書かず、次に開いたときにまた知らせる (それまで歯車の点は残る)。スキップは `config.ini` の `update_skip` にその版を書き、次の版が出るまで知らせない。
- **今すぐ更新**: (1) exe と同じフォルダーに `<名前>.update.exe` として受け取る (同じドライブなので入れ替えは名前の変更で済む・書けないフォルダーならここで止める)。(2) 大きさを Releases の `size` と、SHA-256 を `digest` と照合する (BCrypt)。(3) 受け取った exe を `--version` で 1 回起動し、20 秒以内に Releases の版を答えるか確かめる (壊れたファイルやセキュリティソフトに止められる版を入れない)。(4) 動いている exe を `<名前>.prev.exe` に改名し (動いている exe は上書きできないが改名はできる)、受け取った exe をその名前にする。2 つ目に失敗したら改名を戻す。どの段で止まっても exe はそのまま残り、画面は「更新できませんでした — 理由」と「ページを開く」(Releases のページ) に変わる。更新中 (数秒) は録画を始めさせず、題名を「更新中 - Rec Cue!」にして deploy.sh の `--quit` にも閉じさせない。
- **開き直し**: 新しい exe は引数なしで開く (スタートメニューから開いたのと同じ)。最初は `--after-update <pid> --updated-from <版>` を渡して古いプロセスの終わりを待たせる形にしたが、その引数を知らない版 (0.5.0 以前・この試験の入れ替え先) は「unknown argument」で窓を開かずに終わるので、やめた。代わりに古い版が、開く前にショートカットキー 3 つと二重起動の印 (mutex) を手放し、`%USERPROFILE%\.rec-cue\updated-from.txt` に元の版を書く。新しい版は窓を開いたときにそれを読んで消し (2 分より古いものは読まずに消す)、しおりが「{v} に更新いたしました。設定はそのままでございます。」と言う。古い版は新しい版を起動したらすぐ窓を閉じる。新しい窓が手前に出るように `AllowSetForegroundWindow` を渡す。
- **exe のプロパティの版**: 0.5.0 は `res/app.rc` の版が 0.4.2 のままで、配った exe のプロパティも 0.4.2 と出ていた (10-31 に検証用 PC で気付いた)。0.5.1 で直し、`scripts/build.sh` が `src/common.h` の `kVersion` と `app.rc` の 2 か所が食い違えば止まるようにした。
